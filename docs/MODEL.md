# JS-модель логики Ninja (этап 2)

Модель — перевод логики ZX (с исправлениями порта) на JS, по смыслу один к одному: адреса и переменные игры
те же, порядок вызовов и случайных чисел тот же. Это эталон для i8080 (этап 3): каждая функция — одна
подпрограмма ZX, в комментарии её адрес.

## Файлы

| файл | что |
|---|---|
| `src/model/core.js` | `Mem` (64 КБ в раскладке ZX, очереди портов и `LD A,R`, звуковые события), записи бойцов/оружия |
| `src/model/sys.js` | ГСЧ `$DECA`, печать (только след: `$DEF5..$DEFA`), очистка экрана, имена `$F5F2`, `$E2B4` |
| `src/model/fight.js` | попадания `$EF3F`, удар `$EE4B`, нокаут `$EE91/$EEE6/$EF24`, гибель `$EE29`, оружие `$F3C3/$F40D/$F476/$F277` |
| `src/model/actors.js` | бросок врага `$E4FC`, ИИ `$E583..$E827`, анимация `$FB71`, `$F4AC`, полоски `$EDC2`, герой `$FC78..$FDDB`, ввод `$E1F4` |
| `src/model/room.js` | переход `$F699`, враги по комнатам `$E336`, постройка `$EABC` (поток, пол, дыры, идол, стены), разворот спрайтов `$F925`, расстановка `$F97E/$FA3D`, след вывода `$E8AB` |
| `src/model/game.js` | проход `$ED23` (`pass`), новая игра `$EC2D` (`new_game`), идол `$F554`, очки `$EA76` |
| `tools/zxgold.js` | чтение эталонов и Z80 (`tools/vendor/Z80.js`), проигрывающий их точно |
| `tools/model_run.js` | сверка модели с Z80 по эталонам |

## Договорённости

- **Не рисует.** Записи ниже `$7300` (экран, атрибуты, задний буфер) не делаются. Всё, что вывод ZX оставляет
  в памяти игры, модель повторяет: кадр бойца (`+2/+3` размер, `+6/+7` данные), адреса в буфере и на
  экране (`+4/+5`, `+A/+B`), флаги поля `$E2D2–$E2D4`, состояния оружия (`+A`), указатели печати,
  самоизменяемые операнды (`$FE25`, `$FF51`, `$F91B`). Разворот спрайтов при смене направления (`$F925`)
  переписывает данные кадров в памяти — модель делает то же.
- **Странности ZX сохранены**, они влияют на ход игры. `$E4B3` в новой игре (поле +7 бойца 5, а не +8).
  `$FA8F` смотрит только первый слот врагов. `$FA4B` пишет `$FF` в `$E88B`. Проверка дыры в полу
  `$FDB0` (третья позиция без `CP`). `$DEF1 = 0` в `$E7D2`. `$DFE1` — то сохранённый SP, то временная
  ячейка ИИ.
- **SP**: очистка экрана сохраняет SP в `$DFE1`. Поэтому `next_room(M, dir, sp)` получает SP на входе в
  `$F699`: `$FFFC` из действий героя, `$FFFE` из новой игры.
- **Не моделируется**: меню, переопределение клавиш, GAME OVER, WINNER, выход в меню по F (`NotModeled`).
  На Векторе — свой фронт.
- Звук — список событий `M.snd` (`hit`, `room`, `idol`): точки запуска для озвучки Atari (этап 5).

## Сверка

```sh
tools/goldens.sh                                   # эталоны ZX (≈5 мин), build/golden/
node tools/zxgold.js build/golden/g0_play.jsonl.gz # Z80.js = SkoolKit (самопроверка)
node tools/model_run.js build/golden/g*.jsonl.gz   # модель: 0 расхождений (≈25 с)
node tools/model_run.js build/golden/g0_play.jsonl.gz --neg   # негативный контроль: должно краснеть
```

На каждом шаге модель стартует с памяти Z80 и получает те же порты и `LD A,R`. Потом она сравнивается с
Z80 по всем адресам `$7300–$FF7F`, которые записал Z80 или модель. Кроме того, «новая игра»
(`$EC2D..$ED23`) сверяется отдельно на каждом проходе через меню. Остаток очередей портов и `LD A,R`
тоже считается расхождением.

Итог 14.11.2026: 12 эталонов, 15 406 шагов, из них 15 375 сверено — **0 расхождений**. Без модели 31 шаг (GAME OVER, WINNER,
F). 31 новая игра совпала.

## Чего эталоны не проходили (модель переведена, но не проверена)

Бросок, когда боец ниже Y=`$28` (`$F4AA`). Нокаут во время гибели героя. Нет выхода влево/вправо
(`$FD0F/$FD2C`, `$F921`). Kempston ≥ `$1B` (`$E216`). Переполнение счёта за 5 цифр. `$FA27` недостижим:
`$E85C` к этому месту перезаписан анимацией.
