# Ninja (ZX): данные игры

Извлечено 14.11.2026 скриптом `tools/extract_data.py` из проверенного образа
`build/zx/ram4000.bin`. Результат — в `data/`, картинки для просмотра — в `data/png/`.

```sh
tools/.venv/bin/python tools/build_skool.py            # образ + проверка
tools/.venv/bin/python tools/extract_data.py           # → data/
# сверка с игрой: дампы памяти при старте в каждой комнате
for r in $(seq 0 20); do h=$(printf %02X $r); tools/.venv/bin/python tools/run_trace.py \
  build/snap/ninja.z80 build/rooms_rt/r$r --hist --frames 160 --keys "50-54:1,80-84:0" \
  --at "0@FB40:E4BA=$h" --dump "0@ED23:4000+4D60"; done
tools/.venv/bin/python tools/extract_data.py --check build/rooms_rt
```

## Сверка

Для каждой из 21 комнаты игра запускалась сразу в ней (подмена `ROOM` на `$FB40`, сразу
после выбора соседа), и в начале главного цикла снимались экран, атрибуты, задний буфер и
`TILE_MAP`. Результат декодера совпадает с игрой:

- **карта тайлов** 672 клетки — 21/21 комната без расхождений;
- **атрибуты** 672 клетки — 21/21 без расхождений;
- **пиксели** заднего буфера — совпадают везде, кроме того, что рисуется не тайлами:
  дыры (5 клеток в рядах 0–1 / 19–20), идол (2×2 клетки, ряды 18–19, столбцы 27–28)
  и 3 клетки, которые портит прерывание ПЗУ: `$5C01`, `$5C05` (KSTATE), `$5C78` (FRAMES)
  лежат внутри заднего буфера `$5B00–$72FF` — это и есть механизм ошибки 1 багфикса.

## Комнаты (`data/rooms/`, `data/rooms.json`, `data/png/room*.png`)

Сборка комнаты (`ROOM_BUILD $EABC`), в этом порядке:

1. **Атрибуты тайлов** `TILE_ATTR $E37E` с двумя правками на комнату: тайл `$25` = `$2C`
   в комнатах 4, 6, 8, 3, 5 (`$F694`), иначе `$2A`; тайл `$A0` = `$30` и пустой в комнате 1,
   иначе `$28` и копия графики тайла `$9C`.
2. **Верх** — поток из `ROOM_STREAMS $D9DE`: ряды по **40** столбцов, видны 4..35 (32),
   480 видимых клеток = ряды 0–14. Байт `t` — тайл, `$FF t n` — тайл `t` `n+1` раз.
   Атрибут клетки = `TILE_ATTR[t] | $40` (BRIGHT).
3. **Перекраска** (`$EB68`) для комнат из `$EB56`: в N рядах атрибуты `$68–$6F` получают
   синий фон. Индекс в таблицах `$EB50/$EB5C` = 5 − позиция в списке.
4. **Пол** — общий поток `$7808`: 200 клеток с ряда 14, столбца 24 (тот же формат,
   счётчик столбцов с 27).
5. Дыры и идол — рисуются поверх пикселями, в карту не входят.
6. **Стены** (`$F107`): нет выхода влево/вправо → блок 4×15 тайлов из `$8134` / `$8158`
   (источник — ряды по 40) в столбцы 0–3 / 28–31, ряды 2–16.
7. После копии в задний буфер: **радуга** в комнате 0 (ряды 4–10, фон 1..7, `$F817`) и
   **двери** в комнатах 19/20 (атрибуты 8×8 с ряда 5, столбца 12: `$50` красная,
   `$60` зелёная, `$FF48`).

`rNN.map` — 672 номера тайлов (21×32), `rNN.attr` — 672 атрибута, ровно как в игре.

**Связи.** `NEIGHBOURS $D897`: на комнату 4 байта — влево, вправо, вверх, вниз, номер
соседа +1 (0 — нет выхода). В `rooms.json` — поле `exits`. Новая игра: `ROOM=6`, шаг
вправо → **комната 4** (Torii in the Sea).

## Враги

`MAX_ENEMIES $DA70` — число мест в комнате. `CLEAR_ROOM_TABLES $E336` при новой игре
**и при каждом переходе вверх/вниз** заново расставляет врагов во всех комнатах: каждое
место, кроме последнего, занято с вероятностью 191/256, последнее — всегда; тип случайный
1..3 (THUG, KARATEKA, NINJA), байт `$F0+тип` (энергия 15 в старшей тетраде) в
`ROOM_ENEMIES $DA85` (5 байт на комнату). Имена — `ENEMY_NAMES $F61C`.

## Кадры бойцов (`data/frames/`, `data/frames.json`, `data/png/frames.png`)

`FRAME_TABLE $DA0C`: 50 указателей; кадр = `h, w`, затем `w×h` байт спрайта (по строкам,
бит 7 слева); маска — по адресу кадра + `$2140` (`AND маска / OR спрайт`). В игре
встречаются номера 0..49 (проверено по ходу 8000 кадров). Кадры: ниндзя (чёрный),
громила (в клетку), каратист (белый); герой — тот же ниндзя.

## Мелочи (`data/misc.json`, `data/png/misc.png`)

- `weapons.bin` — 3 значка 8×8 с `$FF62` (звёздочка, кинжал, …); они же метки в строке
  состояния. `weapons_alt.bin` — 3 значка с `$8D57` (горизонтальные, при `IY+4 ≠ 0`).
- `idol.bin` — идол 2 байта × 16 строк (`$FB0A`, накладывается `OR`).
- `hole_floor_edges.bin`, `hole_ceiling_edges.bin` — края дыр (`$DBDF`, `$DBFF`).
- **Шрифт игры — из ПЗУ Спектрума** (`$3C00`), в образе его нет; для порта нужен свой.
- Названия комнат — `ROOM_NAMES $D900`, 21 строка подряд.

## Не извлечено

- Звук: только бипер (`CLICK`, `ROOM_SOUND`, `SOUND_HIT`) — параметры в коде, не таблицей.
- Таблицы ударов (`$FECA` — какие нажатия атакуют, `$FEF6` — дальность), анимации
  (`$E892`, `FRAME_TABLE`-последовательности) — это логика, разбирать вместе с портом.
- Экран загрузки — `orig/spectrumcomputing/load_Ninja.scr`.
