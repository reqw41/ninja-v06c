# План порта Ninja (ZX) → Вектор-06Ц

Образцы — **brucelee-v06c** (`docs/PLAN.md`, `docs/JOURNAL.md`, `docs/VEC_LAYOUT.md`, `src/vec/*`,
стенды `tools/run80.js`, `vecroomcheck.js`, `vecsoak.js`, `vecevent.js`) и **pyjamarama-v06c**
(`docs/PORT_PLAN.md`, `docs/REUSE.md`: что брать из готовых портов; `docs/MODEL_GUIDE.md`,
`NATIVE_GUIDE.md`), общие уроки — `aticatac-v06c/docs/LESSONS.md`. Разбор ZX — `docs/MAIN_LOOP.md`,
данные — `docs/DATA.md`, звук — `docs/MUSIC.md`, история — `docs/JOURNAL.md`.

## Решения владельца (14.11.2026)

- **Экран: 3 плоскости, 8 цветов.**
- **Управление — схема Bruce Lee.**
- **Звук — озвучка ровно как в Atari** (песня, подыгрывание при враге, эффекты, тикание), на
  **всех 3 счётчиках ВИ53** + спикер; проигрыватель в прерывании (подход Bruce Lee).
- Из ПЗУ ZX ничего не переносится (шрифт — свой).
- Ближний бой врагов — исправить (`$EF4F`), как у CPC; номер комнаты — отдельная ячейка (багфикс 2);
  ошибка 1 (прерывания ПЗУ) на Векторе не возникает.

## Экран (как Bruce Lee)

| адрес | что |
|---|---|
| A000, C000, E000 | видимые плоскости: бит 2 (зелёный), 1 (красный), 0 (синий) цвета ZX; **номер палитры = цвет ZX** |
| 8000–9FFF | невидимая плоскость = ОЗУ (палитра парами: номер i и i+8 одинаковы) |

- Ninja использует **ровно 8 цветов**: чёрный и 7 ярких ZX (`BRIGHT` у всех цветных клеток;
  проверено по всем 21 комнате: 4–8 цветов на комнату, всего 8). Палитра одна на всю игру,
  без потерь, клэша нет.
- Экран ZX 256×192 → строки 32..223 Вектора: строка ZX `L` в столбце `c` плоскости `P` —
  байт `(P + c)·256 + 223 − L`. Следующая строка — `DEC L`, а не `NEXT_ROW` с третями ZX.
- **Без заднего буфера ZX** (`$5B00`, 6 КБ): каждый байт экрана пишется один раз итоговым
  значением (тайл под бойцом из `TILE_MAP` + спрайты бойцов по маске), перерисовываются только
  изменившиеся бойцы (полоса столбца, как STRIP в Bruce Lee). Это убирает `DRAW_FIELD` (40 %
  времени ZX) и `CLEAR_ACTOR_RECTS`.
- Вид бойцов по умолчанию — **как ZX**: точка спрайта — цвет чернил клетки, точка, очищенная
  маской, — цвет фона клетки (по `rNN.attr`). Вариант с цветами CPC — потом, если владелец захочет.

## Управление (как Bruce Lee, `plat.asm`)

- Клавиатура ZX эмулируется: `zx_kb` — 8 рядов ZX из матрицы Вектора; опрос **только в начале
  прерывания** (порт 03 — ещё и прокрутка).
- Игрок: **стрелки + пробел** и **джойстик «П»** (оба порта); буквы ZX не управляют.
  У Ninja огонь + направление = приёмы — пробел/огонь с направлением работают так же.
- **ВК** — пауза, **АР2** в паузе — в титул, **УС** — звук вкл/выкл.
- Меню ZX (Keyboard/Kempston/Cursor/Sinclair/Redefine) упрощается: управление всегда
  «клавиатура + джойстик», пункт меню — только старт.

## Звук (озвучка Atari, docs/MUSIC.md)

- Модель всей звуковой системы Atari — `tools/atari/sound.py` (0 расхождений с MAME за 8821 кадр);
  её и переводим на 8080: песня (трекер `$BC10` с данными как есть), подыгрывание, свист, эффекты боя,
  «тук», тикание счёта.
- Канал POKEY 1–3 → счётчики ВИ53 0–2 (режим 3), делитель (AUDF+1)·47; голос звучит, пока громкость
  > 0; шум и 4-й канал POKEY (свист, тикание) → спикер (ВВ55); темп 6 вызовов на 5 кадров.
- Точки запуска — в ZX-логику по таблице `docs/MUSIC.md` (замахи, бросок, попадание, оружие в героя,
  очки, идол, вход в комнату, Game over, враг в комнате → режим, новая игра → песня с начала).
- Секундомера ВИ53 нет (все счётчики — звуку): часы и случайность — от счётчика кадров в прерывании.

## Логика

Как Bruce Lee / aticatac: эталон — ZX (наш `tools/run_trace.py` + сценарии `tools/coverage.sh`),
перевод Z80 → i8080 (механический `z2i` как оракул, горячие места руками), сверка проход в проход
по `MAIN_LOOP $ED23`. Код ZX ≈ 7 КБ (3563 адреса), IX/IY — в таблице бойцов (15 байт на запись) —
переписывать на 8080 через HL/DE, как в Bruce Lee.

Темп: у ZX проход «как успеет» (p50 3,7 кадра ≈ 13,6 тиков/с). На Векторе — фиксированный шаг по
кадрам (кандидат: 1 проход на 4 кадра = 12,5 Гц или 7 на 2 c ≈ 13,6 Гц) — решить после замера.

## Память (оценка, ванильные 64 КБ)

| что | КБ |
|---|---|
| экран (3 плоскости A000–FFFF) | 24 |
| кадры бойцов (спрайт + маска) | 16,4 |
| потоки комнат + пол + стены | 6,5 |
| тайлы + атрибуты тайлов | 1,9 |
| тексты, имена, шрифт (свой, только нужные знаки), мелочи | ~1,5 |
| код i8080 (≈ 1,4 × ZX) + звук | ~11 |
| карта тайлов, переменные, стек, полоса столбца | ~1,5 |
| **итого** | **~63** |

Впритык: 0000–9FFF (40 КБ, включая невидимую плоскость) против ~39 КБ без экрана. Запасы, если
не влезет: ZX0 для потоков комнат (как в Bruce Lee: дыры под код), маски кадров, которые
восстанавливаются из спрайта (проверить), общие кадры героя и ниндзя (тот же рисунок).

## Этапы (по опыту Bruce Lee и Pyjamarama)

Схема обоих портов: **эталон ZX → JS-модель логики (0 расхождений) → i8080 по модели (0 расхождений
с теми же эталонами) → игра на Векторе (вывод, ввод, звук) → фронт → образы и гейты**. Логика и вывод
разделены: модель и i8080 не рисуют, а отдают список «что нарисовала бы ZX» (у Ninja: бойцы — X/Y/кадр,
снаряды, дыры, идол, полоски энергии, счёт), Вектор выводит это сам.

### 0. Разведка — сделано
Вход, главный цикл, вывод, покрытие 15 сценариями, ошибки оригинала, сверка с CPC, данные 21 комнаты
1:1, звук Atari (модель 1:1, события проверены по экрану). См. `docs/JOURNAL.md`.

### 1. Эталоны ZX по проходам — сделано 14.11 (`tools/goldens.sh`, 11 эталонов, ≈14 тыс. шагов, покрытие 3609 адресов; `docs/JOURNAL.md`)
- Записыватель на нашем `tools/run_trace.py`: шаг = проход `MAIN_LOOP $ED23`; на шаг — ввод (порт `FE`,
  Kempston), чтения `R` (ГСЧ `$DECA` сеется `LD A,R` один раз — `$DEF1`), изменения памяти игры
  (`$D000–$FF7F` без вывода и заднего буфера), список вывода (вызовы `DRAW_ACTORS`, HUD, комната).
- **Эталон — ZX с исправлениями порта**: `$EF4F: B4` (ближний бой), багфикс 2 (комната `$E4BB`),
  прерывания выключены (как на Векторе — нет порчи `$5C01/$5C05/$5C78`). Чистый оригинал — отдельно,
  для сравнения.
- Сценарии — из `tools/coverage.sh` + «тур» по 21 комнате (подстановка `ROOM` на `$FB40`), все враги,
  идолы, WINNER, GAME OVER; политика «бот» для долгих прогонов. Цель — ≥95 % покрытия логики.

### 2. JS-модель логики — сделано 14.11 (`src/model`, `tools/model_run.js`, 12 эталонов — 0 расхождений; `docs/MODEL.md`)
- Модули: бойцы (`MOVE_ENEMIES`, `HERO_ACTION`, `ENEMY_STATE`, анимация, `ENEMY_AI`), удары
  (`CHECK_HITS`, `HIT_HANDLER`, `KO_HANDLER`), снаряды (`PROJECTILES_*`), комнаты (`NEXT_ROOM`,
  `ENTER_ROOM`, `ROOM_BUILD` → данные `data/`, дыры, стены, расстановка врагов `$E336`), идолы, счёт
  (`SCORE_TICK`), смерть/WINNER/GAME OVER, ввод.
- `tools/model_run.js` по эталонам этапа 1 — 0 расхождений; сверка по подпрограммам (shadow) для
  отладки; негативный контроль (порча — красный).
- Попутно в модель — точки звука (события `docs/MUSIC.md`) и звуковая модель Atari (перевод
  `tools/atari/sound.py` на JS) — эталон для этапа 6.

### 3. Логика на i8080 — сделано 14.11 (`src/i8080`, `tools/run80.js`, 0 расхождений; `docs/I8080.md`)
- По модели, руками; запись бойца 15 байт (IX/IY у ZX) → рабочая копия текущего бойца (как `pw` в
  Bruce Lee), без индексных регистров. Механический Z80→8080 (`pyjamarama/tools/z80to8080.py`) —
  оракул и оценка размера.
- `run80.js`-аналог: i8080 по эталонам шаг в шаг, 0 расхождений; такты на проход (`--prof`).

### 4. Платформа и вывод на Векторе — в основном сделано 14.11 (`src/vec`, `tools/vecstep.js`; `docs/VECTOR.md`)
- Раскладка памяти (`docs/VEC_LAYOUT.md`), загрузка `.r0m`, прерывание: палитра 8 цветов ZX
  (номер = цвет), клавиатура → `zx_kb`, стрелки/пробел/джойстик «П», ВК/АР2/УС — `plat.asm` Bruce Lee.
- **Комната**: декодер потока + пол + стены + перекраски прямо в 3 плоскости (`TILE_MAP` и атрибуты —
  в ОЗУ для вывода бойцов); гейт — 21 комната против `data/rooms` (`vecroomcheck`).
- **Бойцы без тени**: замещение на месте по полосе столбца — тайл под бойцом из `TILE_MAP` + маски и
  точки всех бойцов в клетке, точка — чернила клетки, дырка маски — бумага; каждый байт пишется один
  раз; рисуются только изменившиеся (у ZX до 6 бойцов, 7×60). Снаряды, дыры, идол, HUD (свой шрифт).
- Темп: фиксированный шаг по счётчику кадров (решить: 1 проход на 4 кадра = 12,5 Гц или ≈13,6 Гц как
  ZX p50); смена комнаты — с эффектом `ROOM_TRANSITION`.
- Гейты: `run80 --ship` (боевой образ по эталонам), сверка экрана с композицией, долгая случайная
  игра (зависания, PC/SP), вызов редких событий.

### 5. Звук (озвучка Atari)
- 8080-перевод звуковой модели: песня (данные `data/music/atari_bc00.bin`), подыгрывание, свист,
  эффекты, «тук», тикание; ВИ53 ×3 + спикер; вызов 6 раз на 5 кадров.
- Сверка 8080 против `tools/atari/sound.py` покадрово (записи «регистров POKEY» до перевода в ВИ53);
  на слух — Emu80 и MiSTer.

### 6. Фронт
- Титул/меню (одна строка «старт»), «APPROACHING <комната>», пауза, GAME OVER, WINNER и новый круг.
- Заставка (как Bruce Lee/Pyjamarama: картинка в ZX0, показ один раз): кандидаты — экран загрузки ZX
  `load_Ninja.scr`, титул CPC, титул Atari — выбор владельца. Русская версия — по желанию.

### 7. Выпуск
- Образы `.r0m/.c00/.mgl` с 0x0000 и `.rom` с 0x0100 (как Bruce Lee), ZX0-упаковка игры.
- Гейты: нет опкодов Z80 в образе (`check_i8080`), зависания, ввод, палитра; проверка на MiSTer
  (`mister-deploy`), Emu80 — одна версия (английская или русская).
- README по шаблону портов, публичный репозиторий (чистая копия без `orig/`).

### Риски и решения владельца
- **Память** (~63 КБ из 64): если не влезет — ZX0 потоков комнат и заставки, дыры под код (как Bruce
  Lee), общие кадры героя и ниндзя, проверить восстановление масок из спрайтов.
- **Скорость**: логика дешёвая (< 10 % у ZX), всё время — вывод; замещение на месте вместо перерисовки
  поля должно дать запас. Мерить на этапе 4.
- Открыто для владельца: темп; вид бойцов (как ZX — чернила клетки, или цвета Atari/CPC); заставка;
  русская версия.

## CPC-версия в эмуляторе

`tools/cpc/run.sh OUTDIR` — MAME `cpc6128` без окна и звука, дискета MT0015, ПЗУ из
`$CPC_ROMPATH` (по умолчанию `~/projects/knightlore-research/cpc/roms`). Сценарий —
`tools/cpc/play.lua`, через переменные окружения:

```sh
NINJA_FRAMES=6500 NINJA_SHOT_EVERY=300 \
NINJA_KEYS="2300-2340:2,2450-2490:0,2700-3100:R,3100-3160:R+F,3400-3800:R" \
NINJA_PEEK="3400/50:7440-7481" tools/cpc/run.sh build/cpcrun/play
```

- `NINJA_KEYS`: `кадры:клавиши`; R L U D F — джойстик (меню «2»), иначе имя клавиши MAME или
  её первый знак (`0`, `2`, `p`, `Space`). Клавиши меняются только на границах интервалов
  (иначе ломается набор `RUN"NINJA`).
- Загрузка: `RUN"NINJA` на кадре 120, заставка, меню (0 старт, 1 клавиатура, 2 джойстик)
  готово к ~2300 кадру; раньше нажатия меню не видит.
- `NINJA_PEEK`: печать памяти; снимки — `OUTDIR/snap/cpc6128/*.png` (768×272).
