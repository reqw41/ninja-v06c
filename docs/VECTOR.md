# Ninja на Векторе: платформа и вывод (этап 4)

Сборка — `./build.sh`: `build/vec/ninja.bin` (0000–9FFF), `build/vec/ninja.rom` (с 0100, старт 0100),
`build/vec/ninja_t.bin` — то же со шрифтом ПЗУ ZX, **только для сверки экрана** (в порт не входит).

## Платформа (`src/vec/plat.asm`)

- Запуск: ППА, джойстик «П», ВИ53 в тишину (звук — этап 5), вектор 0038, палитра ZX (номер = цвет ZX, 8 цветов
  дважды: плоскость 8000 — код). Пока без заставки и меню (этап 6): огонь/пробел — новая игра, ГСЧ сеется
  счётчиком кадров (у ZX — `LD A,R`).
- Прерывание: палитра, опрос клавиатуры (только в начале прерывания), счётчик кадров.
- Ввод как Bruce Lee: стрелки + пробел и джойстик «П» -> Kempston ZX (тип управления 1); ВК — G ZX (пауза до
  клавиши управления), АР2 — F ZX (выход). Буквы ZX не управляют.
- Темп: вывод ждёт `TICK` = 4 кадра с прошлого вывода (ZX — p50 3,7 кадра на проход).
- GAME OVER / WINNER — строка ZX, огонь — новая игра.

## Вывод (`src/vec/render.asm`)

Без заднего буфера ZX. Поле (строки ZX 0..20) собирается по столбцам в полосе `STRIP` (байт на строку):
тайлы `TILE_MAP` → дыры (FF + края) → идол → бойцы 5..0 по маске → оружие; потом полоса раскладывается в
3 плоскости по цвету клетки `AMAP`: плоскость = (точки & (чернила ^ бумага)) ^ бумага. Перерисовываются
только прямоугольники изменившихся бойцов (старое ∪ новое, целыми клетками), оружия (как ZX: нарисовано /
стёрто в проходе — флаги `pj_dr`/`pj_er` из логики), идола; полоски энергии — при смене энергии.

- Комната: `AMAP` из атрибутов тайлов + перекраска `$EB68`, радуга комнаты 0, двери 19/20; всё поле.
- HUD: печать строк ZX (`$16` AT, `$11` цвет) своим шрифтом (`tools/mkfont.py`), двойная высота для
  APPROACHING; перекраска строк HUD (`$F5CB`) восстанавливает точки из плоскостей.
- Экранная строка: i = 191 − строка ZX (как таблица `$D717`), байт Вектора — (A0+столбец)·256 + 32 + i.

## Сверка (`tools/vecstep.js`)

Боевой образ (`ninja_t`) шаг в шаг с Z80 по эталонам: память игры переносится, экран Вектора остаётся
свой, после прохода сравнивается с экраном ZX (точки ZX, раскрашенные атрибутом ZX). Расхождения делятся:
поле, HUD, клетки под оружием (ZX прячет оружие под прямоугольниками бойцов, Вектор рисует поверх),
прямоугольники копирования бойцов ZX (ZX режет ими спрайты и затирает HUD).

Итог 14.11 (12 эталонов, ≈15 тыс. шагов): HUD — 0; поле — 0 на 9 эталонах; g2 — 2 шага, g3 — 14, g1 — 36,
g7/g8 — 10/9: следы ZX (недостёртые куски при подъёме через дыру, обрезки спрайтов на краях прямоугольников).

Такты прохода с выводом: p50 149 тыс. (2,5 кадра), p90 306 тыс. (5,1; у ZX p90 — 5,9 кадра). Переход со
сменой направления — до 7 млн (≈1,8 с: разворот 50 кадров обменом на месте + постройка).

## Память

Комнаты (14.11): потоки 20 комнат в ZX0 (5032 → 1796 Б, `tools/mkl80.py` → `gen/rooms.asm` с `2000`),
распаковка в `AMAP` при постройке комнаты (его затем строит `plat_room`); пол — как есть, стены — табличка
4×15 ×2 (у ZX — невидимые столбцы данных комнаты 10). Свободно `2874–37B6` (3907 Б).

Низ: код до `18FF` (запас 1,8 КБ до `2000`). Верх: вывод и шрифт `8DC5–992B`, `AMAP 9B00`, полоса `9E00`,
стек `9F00–9FFF`; свободно ≈470 Б под `AMAP`.

## Вид CPC (решение владельца 14.11: кадры CPC целиком, палитры комнат как CPC — схема Bruce Lee)

- Кадры бойцов — CPC (`orig/` CPC, NINJA3.BIN: таблица `$79D1`, 48 кадров RLE режима 0, перья 1 чёрное,
  2 телесное, 3 оранжевое; составные `$7DC1` — для кадров ZX 46..49). Нумерация как у ZX (34..45 -> +2).
  Привязка к рамке кадра ZX — по совпадению силуэтов (0,51..0,84), сдвиг кратен 4 точкам. `tools/cpcspr.py`,
  `tools/mkcpc.py` -> `src/vec/gen/cpc.asm` (RLE как у CPC, 10,4 КБ) — на месте спрайтов ZX (логика их больше не
  разворачивает: `VEC_CPC`, направление — `$F924`, разворот при распаковке).
- Кадры хранятся распакованными по столбцам (владелец 14.11: «сразу хранить в нужном формате»): на столбец —
  строки r0..r0+n-1 по 2 байта (P0, P1), прозрачные края не хранятся (12,6 КБ + таблицы 1,3 КБ). Разворот —
  как ZX: при смене `$F924` все кадры переворачиваются на месте (`spr_orient`: обращение битов + обратный порядок
  столбцов). Столбец экрана собирается в 3 невидимых полосах (3200/3300/3400: фон, затем бойцы) и копируется на
  экран — каждый байт экрана пишется один раз (владелец: «стирание и перерисовку видно»). Бойцы в полосах: A &= ~M, C = C & ~M | P1, E = E & ~M | (P1 & ~P0) (номера 0 чёрный, 2 оранжевый,
  3 телесный).
- Палитры (`tools/cpcpal.py`): голосование цвета CPC под каждым цветом ZX по снимкам 21 комнаты CPC (MAME, тур
  телепортом: комната `$72E9`, X героя `$7442`, соседи `$7828`), отдельно верх (строки 0..13) и пол (14..20);
  на комнату — 5 своих цветов + 3 общих бойцам; `AMAP` хранит номера палитры. HUD — телесный на чёрном,
  APPROACHING — своя палитра (жёлтый). Предпросмотр — `build/cpc/rooms_recolor.png`, кадры — `docs/cpc/cpc_frames.png`.
- Сверка экрана (`tools/vecstep.js`): цвета поля — через таблицы перекраски, клетки бойцов не сверяются.
- Ускорение (14.11): кэш кадров на 10 мест, наложение бойцов на регистрах, слияние перекрывающихся прямоугольников
  перерисовки (`rl_flush`), фон прямо из тайлов в плоскости в столбцах без дыр/идола/оружия (`col_fast`), пустые
  клетки — заливка бумагой. Такты прохода с выводом: p50 181 -> 154 тыс. (2,6 кадра), p90 425 -> 300 тыс. (5 кадров).

## Геометрия оригинала ×1.5 (владелец 14.11: «привести к координатам Atari и CPC», вариант 1.5)

- У Atari (ANTIC E, 160×176) и CPC (режим 0, 160×200) комната — 40 тайлов по 4 точки; у ZX видно 32 средних.
  У Вектора комната — 40 тайлов по **6 точек** (240 точек) от x = 8: столбцы экрана 1..30, 0 и 31 — чёрные поля.
  Точка ZX x -> 32 + 0,75x, столбец ZX X -> тайл X + 4; тайл 8 -> 6 точек (точки ZX 0,1,3,4,6,7:
  `src/vec/gen/tiles6.asm` на месте тайлов ZX, логика по-прежнему копирует тайл 156 -> 160). Вертикаль — как была.
- Карта: тайлы 4..35 — карта ZX `MAP_V` (логика строит её без стен ZX: `walls` под `IFNDEF VEC_CPC`), поля
  0..3 / 36..39 — `MARG_T` (21×8, `marg_build` из потоков комнаты и пола, стены — при отсутствии соседа),
  атрибуты — `AMAP` и `MARG_A` (перекраски ZX, радуга комнаты 0 и цвета CPC — на всю ширину). Дыры и идол —
  свои тайлы (неиспользуемые номера, `ct_hc`/`ct_hf`/`ct_idol`: точки тайла | узор), идол взят — исходные тайлы.
- Столбец экрана b: f = 8(b-1), t0 = f / 6, o = f % 6 (`col_t0o`); байт = тайл t0 << o | тайл t0+1 >> (6-o)
  (`bg8_0/2/4`), цвет клетки — маски двух тайлов (`pm_tab`, 64 атрибута), смешанные по Mf = FC/F0/C0.
  Столбец без оружия — за один проход по клеткам (сборка + цвета), с оружием — сборка, оружие, цвета.
- Бойцы: кадры CPC ×0,75 (точка n кадра = точка CPC (n + 0,5)·4/3 - dx делённая на 2), заголовок ox — в новых
  точках от левого края рамки ZX. Позиция = 32 + 6X + ox (разворот: 6wzx - ox - 8wv), сдвиг s = позиция & 7
  (0, 2, 4, 6): столбец данных d даёт столбцу экрана col0 + d часть rotr(байт, s) & (FF >> s), соседнему — остаток.
  Бойцы в полях 0..3 / 36..39 видны (как у CPC). Оружие — картинки 6 точек (`p6_ff62`, `p6_8d57`) со сдвигом.
- Сверка: поле — против своей отрисовки 40 тайлов по памяти ZX (`field40` в `tools/vecstep.js`, независимая
  от асма: потоки, стены, перекраски, дыры, идол — на момент вывода), клетки бойцов и оружия не сверяются; HUD —
  против экрана ZX. Карта и тайлы ZX в Вектор не переносятся, экран комнаты строит `room_build` Вектора.
- Цена: такты прохода с выводом выросли ≈ на 35 % (g2: p50 162 -> 216 тыс., p90 279 -> 386 тыс.; g1 p50 300 -> 412 тыс.):
  сдвинутый боец накладывается двумя частями на столбец, фон собирается из двух тайлов со сдвигом.

## Комнаты и шрифт CPC (владелец 15.11: «графику комнат и раскраску полностью с CPC, и шрифт надписей»)

- CPC рисует комнату по тем же потокам ZX (те же номера тайлов, NINJA3.BIN `$3234` = ZX `$7300`): тайлы `$4721`
  (16 байт: 8 строк по 4 точки режима 0, перья 0..3), затем перекраска строк экрана по списку комнаты `$7A31`
  (строка 199 - c, b строк вниз, перо «из» -> «в»), чернила `$7C54..$7C63`. Всё взято из снимка памяти CPC
  (MAME, `build/cpcrun/dump/ram.bin`) — `tools/cpcroom.py` (макет `build/cpc/cpcrooms.png`).
- Вектор: тайл ×1.5 — 2 плоскости пера (бит 0 — `gen/tiles6.asm` на месте тайлов ZX, бит 1 — `tile_b`); столбец
  экрана собирается для обеих плоскостей пера (`STRIP`, `STRIP2` = страница `AMAP`+1), затем на строку: номер
  плоскости k = f_k(перо) — 16 подпрограмм `gen/plfun.asm`, функции по полосам строк комнаты `room_runs`
  (3..13 полос). Палитра комнаты — цвета CPC (до 8; чёрный 0, оранжевый 2, розовый 3 закреплены за бойцами;
  в комнате 2 девятый цвет слит с ближайшим). Дыры — перо 1, идол — перо 3, оружие — перо 3.
- Атрибуты ZX и перекраски ZX для поля больше не нужны (`AMAP` — только HUD и APPROACHING).
- Шрифт — CPC (`$7C51` + 8 × код, цифры и заглавные, `data/cpc/font.bin` -> `tools/mkfont.py`).
- Края комнаты: переход и стены на 4 тайла дальше (комната 40 тайлов; `EX_D` в `actors.asm`), кроме сборки
  сверки `ninja_t` (шаг в шаг с ZX). Сверка поля — своей отрисовкой CPC по снимку памяти CPC, 0 расхождений.
- Такты: g2 p50 266 тыс., p90 474 тыс. (+18 % к ×1.5 на атрибутах) — две плоскости пера и функции плоскостей.
